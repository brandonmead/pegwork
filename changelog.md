# Pegwork changelog

Purpose: dated, newest-first log of changes actually made.

## 2026-10-20
- UX polish and 0.2.0 (in review, branch `ux-polish`): plugin version 0.2.0 (header, `PEGWORK_VERSION`, readme, package); manifest `requires` documented as informational. Schema error notices and Overview rejected rows show paths relative to `wp-content/` or the package (`Registry\Status::display_path()`) plus the JSON pointer; the CLI keeps absolute paths. Module labels and descriptions translated at read time (closures around `__()`, resolved after `init`). Confirmations that fail re-validation tell the submitter a person will check (`messages.confirm_failed`, schema and builder setting, `pegwork_review=1`). Turnstile forms: submit button disabled (faded) until an inline script enables it; a POST with no token field is stored as spam `captcha_missing` and told the form needs JavaScript (an empty or rejected token stays `captcha_failed`). Form builder: Summary status and publish rows removed, Save draft hidden, Publish relabeled Save, pre-save panel without its Visibility and Publish rows; file forms hide the inserter and "Last edited" and keep their modified date on sync; bound field labels at full contrast. Entries: destructive Delete permanently buttons with a visible focus ring, bulk actions and form filter kept at 782 px, no stray ": " in the Errors row. Forms list column widths, block markup wrapping at spaces and keys breaking after underscores; Modules slugs no longer break mid-word; options page post picker opaque and full width at 782 px. Unused eslint directive removed; `docs/e2e.md` warns that Turnstile pages never reach network idle. Tests in `AdminOverviewTest`, `SifgExampleTest`, `ModuleLoaderTest`, `FormsRecordsTest`, `FormBuilderTest`, `FormsTurnstileTest`, `PluginLoadsTest`; E2E `forms-turnstile.e2e.js` (disabled button, no-token POST), `admin-a11y.e2e.js` (every Pegwork screen at 1280 and 782 px, no horizontal scroll), `forms-builder.e2e.js` (read-only chrome, Save label), `forms-entries.e2e.js` (destructive button and focus ring). PHPUnit passes on WordPress 7.1.3 and 6.7.10. Screenshots `docs/screenshots/ux-*.png`.
- Related records in listings (in review, branch `listings-related`): Query Loop preset `pegwork.where.related: "<relationship key>"` lists the published records linked to the current record (block context `postId`, else the queried post) in both directions through `pegwork_related_query_args()`, keeping the loop's order and paging; no record, no links, a wrong type, an unknown key or a record visitors cannot see list nothing. Constraint `related: { key, post }` in the pipeline and `pegwork_listing_constraints`. "Show if" condition `{ relationship, op: not_empty|empty }` to hide a heading with its loop (core's no-results block cannot). Generated patterns `pegwork/<type>-related-<key>` per relationship end ("Project related Stories"). Editor: "Only records linked to" in the Pegwork directory panel, relationship targets in Show if. `RelatedListingTest` (both directions, nesting in cards, nothing-not-everything cases, condition, patterns, query budget 7 and 9 queries, no N+1), Vitest, E2E `listings-related.e2e.js` (front end both ways, keyboard, axe at 1280 and 782 px, editor panel). Screenshots `docs/screenshots/listings-related-*`.
- `wp pegwork module enable|disable` take several slugs (`<slug>...`), applied in order with a line per slug and exit 1 when any failed (`ModuleCommandTest`).
- Generated `pegwork/<type>-featured` without an options page field now writes `"pegwork":{"filters":false}`: pattern registration re-serialized `{}` as `[]`, which the editor dropped.
- `docs/export-import.md`: export writes six object directories (adds forms, automations, options pages).
